## Слайд 2 — «Бизнес-цели и показатели успеха» (К1)

**Главное сообщение:** «Каждый механизм ИИ привязан к измеримому бизнес-показателю — видно, что работает, а что нет».

**Блок 1. Проблема** (полоса сверху, 3 строки):
14 000 обращений/мес: 71% сортируется вручную · первая реакция 2,5 ч · 16% проблем возвращаются · 11% низких оценок. Цена в деньгах: повторные выезды ~20–30 млн ₽/год, ФОТ на сортировке ~4–5 млн ₽/год, каждый ушедший дом = −7 млн ₽/год выручки; медленная реакция на аварии — лицензионный риск УК.

**Блок 2. Таблица целей** (центральный блок; колонки: показатель / сейчас / цель (5 мес.) / обоснование):

| Показатель | Сейчас | Цель | Обоснование |
|---|---|---|---|
| Ручная сортировка обращений | 71% | ≤30% | прямой эффект классификатора; −41 п.п. ≈ 2+ ставки на рутине |
| Первичная реакция (p90) | ~2,5 ч (среднее) | ≤60 мин; цифровые каналы <1 мин | p90, не среднее: хвост и есть источник жалоб; аварии — нормативы АДС (ПП № 416) |
| Повторные жалобы | 16% | ≤12% | целевая метрика прогнозной модели; повтор = лишний выезд + негатив |
| Обращения с низкой оценкой | 11% | ≤8,5% | интегральный индикатор сервиса глазами жильца |
| **North star: «здоровые обращения»** | ~75% | ≥80% | закрыто без повтора и низкой оценки; нельзя «подкрутить» одной метрикой |

Строка под таблицей — guardrails: пропуск критичной заявки ≤0,5% · возвраты из авто-очереди ≤10% · оценки авто-обработанных ≥ ручных.

**Блок 3. Связь ИИ → бизнес** (три стрелочные цепочки, схемой):
1. Классификатор (F1 ≥0,85; recall критичных ≥0,95) → автомаршрутизация → ↓ реакция, ↓ сортировка
2. Скоринг повтора (lift ≥×2,5 к правилу-бейзлайну) + регламент «топ-10% не закрывать без контроля» → ↓ повторы → ↓ выезды, ↑ оценки
3. Ассистент со статусами (RAG) → ответ <1 мин, 24/7 → ↓ дубли «а что с моей заявкой?» (часть тех самых 16%)

**Блок 4. Почему именно эти показатели** (4 пункта по строке):
1) каждый привязан к своему механизму ИИ — эффект виден попричинно; 2) метрики скорости уравновешены guardrail-ами: одна accuracy обманчива — константа «повтора не будет» даёт 84% при нулевой пользе; 3) повторы запаздывают на 4–8 недель — операционные метрики дают ранний сигнал; 4) цели откалиброваны по рынку: московский ЕДЦ ~30% автоматизации, порог F1 ≥0,85 — уровень внедрения Минюста (0,84–0,89).

Вёрстка: проблема полосой сверху → таблица по центру → цепочки и «почему» внизу в две колонки.

## Слайд 3 — «Данные, технологии и ограничения» (К2)

**Главное сообщение:** «Гибрид: быстрый старт на готовых LLM в российском контуре, к 3-му месяцу — собственная лёгкая модель; персональные данные не покидают РФ».

**Блок 1. Таблица данных** (источник / тип / доступность / ограничения и риски):

| Источник | Тип | Доступность | Ограничения и риски |
|---|---|---|---|
| История обращений | текст, категория, канал, даты | есть | категории неконсистентны → LLM-нормализация |
| Заявки и статусы устранения | структурированные | есть | связки «повтор↔исходная» нет → эвристика: адрес+категория, окно 30 дней |
| Оценки жильцов | балл + комментарий | есть | смещение: чаще оценивают недовольные |
| Телефонные звонки | аудио → текст | **нет записи** | включаем запись + STT (~0,6 ₽/мин); уведомление о записи, 152-ФЗ |
| Справочники (дома, бригады, сезонность) | реестры | частично | чистка и сведение в единую витрину (М1) |

**Блок 2. Технологический подход** — стратегия: **гибрид** (готовые модели + лёгкая собственная + правила):
- старт (недели 1–4): LLM по API из российского контура — классификация + предразметка истории; аварии — только детерминированные правила (ИИ может лишь повышать срочность);
- М2–М3: дистилляция в собственную компактную модель (rubert-tiny2 + CatBoost, CPU) — независимость от вендора;
- прогноз повтора — не LLM: бустинг на табличных признаках + обязательный бейзлайн-правило (модель обязана его бить);
- ИИ-ассистент жильца (веб + бот MAX): RAG по базе статусов; референсы — Госуслуги, Домиленд×А101 (32% заявок закрывает ассистент);
- платформа: российский облачный инференс открытых моделей (Yandex AI Studio / Cloud.ru — DeepSeek V4 Flash, 1M контекст). Выделить плашкой: **инференс ~17 тыс. ₽/мес + распознавание ~19 тыс. ₽/мес = ИИ-инфраструктура <2% бюджета; деньги идут в интеграцию и людей, а не в токены**.

Строка «почему не альтернативы»: с нуля — нет ML-команды и данных; готовая коробка — вендор-лок и непрозрачная экономика; гибрид — старт за 2 недели + собственность на модель и данные к М3.

**Блок 3. Ключевые ограничения** (три колонки):
- **Правовые:** ПДн — только контур РФ (сбор в зарубежные базы запрещён с 01.07.2025); внешние модели — только на обезличенном через шлюз (приказ РКН № 140); запись звонков с уведомлением; утечка = 3–15 млн ₽, повторная — 1–3% выручки.
- **Технические:** возможное отсутствие API у диспетчерской (обход: выгрузки/RPA); потолок эвристики повторов; сезонный дрейф.
- **Организационные:** нет ML-команды → аутсорс с gate-оплатой + перенос компетенций; сопротивление диспетчеров → не сокращаем, доплата за разметку; разметка — узкое место → LLM-предразметка + валидация.

Вёрстка: таблица сверху → подход в середине с плашкой → ограничения тремя колонками внизу.

## Слайд 4 — «План внедрения, риски и экономический эффект» (К3)

**Главное сообщение:** «Первые результаты — через 3 недели; окупаемость — ~10-й месяц; каждый этап закрыт критерием перехода, оплата подрядчика — по факту прохождения».

**Блок 1. Этапы** (левая колонка; этап / содержание / срок / критерий перехода):

| Этап | Содержание | Срок | Gate |
|---|---|---|---|
| М1, нед. 1–2 | ИИ-аудит истории, витрина данных v0, юрподготовка | 2 нед. | карта данных подтверждена; таргет «повтор» воспроизводится |
| М1, нед. 3–4 | Quick wins без ML: автоподтверждение, правила аварий, SLA-таймер, запись звонков, бот MAX v0 | 2 нед. | первые видимые результаты руководству |
| М2 | Классификатор v1 в тени (1 ЖК), поток STT, лайт-ассистент «статус заявки» | 1 мес. | F1 ≥0,80 в тени; ≥60% обращений в единой очереди |
| М3 | Своя модель, частичная автомаршрутизация, скоринг повторов в тени, RAG-ассистент | 1 мес. | F1 ≥0,85; recall критичных ≥0,95; lift ≥×2 |
| М4 | Регламент топ-10% рисковых, контрольная группа 5–10%, расширение автомаршрутизации | 1 мес. | регламент исполняется ≥90%; guardrails чисты |
| М5 | A/B-замер, экономика по факту, передача эксплуатации, решение о масштабировании | 1 мес. | критерии масштабирования ↓ |

Строка под этапами — команда и бюджет: владелец продукта в УК (30%) + аутсорс-DS и инженер (gate-оплата) + оператор «службы заботы» с ИИ (35–50 тыс. ₽/мес) + диспетчеры-разметчики. Бюджет 2,5 млн: разработка 1,25 · интеграция и боты 0,45 · оператор 0,225 · резерв 0,225 · API+STT 0,15 · разметка 0,10 · обучение 0,10.

**Блок 2. Риски** (правая колонка; категория / риск / мера — задание требует ≥3, даём 6):

| Категория | Риск | Мера |
|---|---|---|
| Операционный | ошибка ИИ на аварийной заявке | аварии — только правила; ИИ лишь повышает срочность; guardrail ≤0,5% + еженедельный аудит |
| Данные | история хуже ожиданий, связка повторов не восстанавливается | аудит в первые 2 недели, не в конце; проверка эвристики на окнах 14/45 |
| Организационный | саботаж диспетчеров | в пилоте никого не сокращаем; доплата за разметку; быстрые победы в 1-й месяц |
| Правовой | утечка / трансграничная передача ПДн | контур ПДн в РФ; шлюз обезличивания (приказ № 140); уведомление о записи звонков |
| Стратегический | вендор-лок; срыв сроков подрядчика | открытые веса переносимы; своя модель к М3; gate-оплата; код и данные — собственность УК |
| Технический | сезонный дрейф (отопительный сезон) | валидация по времени; понедельный мониторинг; дообучение по расписанию |

**Блок 3. Экономическая эффективность** (полоса внизу на всю ширину, 4 пункта):
- Подход: в ROI — только прямые измеримые эффекты; замер — A/B с контрольной группой; мягкие выгоды отдельно.
- Выгоды ≈ **7,7 млн ₽/год**: повторные выезды −6,0 млн (−4 п.п. ≈ 6 700 повторов/год × ~70% с выездом × ~1 300 ₽) + сортировка −1,7 млн (5 700 обращ./мес × 4 мин ≈ 2,3 ставки). Атакуемая база по агрессивной оценке — **20–30 млн ₽/год**: расчёт берёт лишь нижний срез. Мягкие вне ROI: удержание домов (ушедший дом = **−7 млн ₽/год**), NPS, лицензионные риски.
- Затраты: проект 2,5 млн (5 мес.) + эксплуатация ≈1,2 млн/год.
- **Окупаемость — ~10-й месяц; ROI первого полного года ≈ +110%**; при эффекте вдвое ниже — окупаемость ~20 мес., проект в плюсе.

**Блок 4. Критерии масштабирования + «почему сейчас»** (две финальные строки):
- Масштабирование при: метрики и guardrails держатся ≥8 недель · факт ≥50% расчёта · новый ЖК ≤2 недель · регламенты живут без ручного управления. Рынок: ~20 тыс. УК; мультитенантность с М1 → через год тираж как SaaS.
- Почему сейчас: цель Минстроя — 75% обращений ЖКХ через ИИ к 2030 · ИИ используют лишь 19% УК — окно раннего большинства.

Вёрстка: самый плотный слайд — этапы слева, риски справа, экономика полосой внизу; таблицы кеглем 11–12, содержимое ячеек телеграфное; развёрнутые формулировки — устно.
