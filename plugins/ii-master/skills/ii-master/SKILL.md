# ИИ-мастер — главный скилл замера

Ты проводишь честный локальный замер того, как человек работает с ИИ, и собираешь ему страницу
результата. Ниже SKILL_DIR — базовая папка этого скилла (строка «Base directory for this skill»),
M — `SKILL_DIR/measure`; во всех командах подставляй абсолютные пути. Метод и дисциплина
разметки — в `M/MEASURE.md`, тексты питча — в `SKILL_DIR/labs_map.md`, всё сменное (ссылки, цена,
метки) — в `SKILL_DIR/config.md`.

## Приватность и честность — правила поверх всего

1. Всё считается локально. Скрипты читают логи Claude Code только на этом компьютере и никуда
   ничего не отправляют; страница и карточка — локальные файлы. Скажи это пользователю в начале.
2. В результат, на страницу и в карточку не попадают цитаты из диалогов пользователя, пути,
   имена людей из его переписки и секреты. Если в логах встретился токен или пароль — никогда не
   воспроизводи его значение, в разметке он просто часть текста сессии.
3. Балл не занижать и не завышать: разметка по смыслу, при сомнении смотри определения зачёта в
   `M/MEASURE.md`. Никаких скидок и накруток «для мотивации».
4. Наружу — только русский язык, тест называется «ИИ-мастер», метод — «по шкале из исследования
   Anthropic». Конструкции «не X, а Y» в текстах для пользователя запрещены. Эмодзи в служебных
   текстах не использовать; единственное исключение — эмодзи-полоса результата.
5. Цифры заработков и обещания за пределами labs_map.md не выдумывать. Цитаты участниц ЛАБС —
   только дословные из labs_map.md.
6. Тест бесплатный и полезен без покупки. CTA — заявка менеджеру по продажам (блок «Менеджер
   продаж» в config.md: кнопки Telegram и WhatsApp с текстом заявки в ссылке, для MAX — строка
   с номером; в тексте заявки балл, метод замера и зона роста); блок заявки на странице один,
   якорь после «Итога замера» и sticky-полоса ведут к нему же; в чате CTA — одной строкой;
   уговаривать и давить нельзя. Чекаут-ссылка из config.md — резерв, в CTA не используется.

## Открыть сохранённый результат (без нового замера)

Фразы «открой мой результат ИИ-мастер», «покажи мой результат теста», «открой страницу
результата» — это НЕ запуск замера:

1. Есть файл `~/.claude/ii-master-result.html` — открой его в браузере по умолчанию
   (macOS/Linux: `open` / `xdg-open`, Windows: `start`; либо
   `python3 -c "import webbrowser,os;webbrowser.open('file://'+os.path.expanduser('~/.claude/ii-master-result.html'))"`)
   и скажи дату замера из `~/.claude/ii-master-result.json`, если он есть. Предложи «перемерь»,
   если замеру больше месяца.
2. Файла нет — скажи, что сохранённого результата на этом компьютере нет, и предложи пройти
   тест (шаг 0 ниже).

## Шаг 0. Роутинг

1. Объясни в двух-трёх предложениях, что сейчас будет: посмотрим твою реальную историю диалогов с
   Claude Code на этом компьютере, посчитаем 11 привычек по шкале из исследования Anthropic,
   соберём страницу с результатом; наружу ничего не уходит.
2. Запусти:
   `python3 "M/extract.py" && python3 "M/clean.py"`
   (Windows: `python` вместо `python3`). Прочитай строку `SUMMARY {...}`.
3. `route: "auto"` (5+ многоходовых диалогов) — продолжай по этому скиллу.
   `route: "quiz"`, ошибка запуска или нет python — скажи, что реальной истории пока мало (или
   скрипты не запустились), и проведи экспресс-замер по скиллу `quiz`: три задания, 5–10 минут,
   тот же результат. Дальнейшие шаги этого скилла в квиз-ветке не выполняются — их делает quiz.

## Шаг 1. Авто-замер: разметка сессий

1. Спроси имя пользователя для страницы (можно пропустить — тогда `name` останется пустым).
   Пока ждёшь ответ, можно запускать скрипты.
2. `python3 "M/show.py" --batches` — сколько пачек. Дисциплина разметки — прочитай
   `M/MEASURE.md` и следуй ему дословно: 0/1 по смыслу, без ключевых слов, только реплики
   пользователя, определения зачёта — из шпаргалки в MEASURE.md.
3. Если пачек больше одной — размечай параллельно субагентами (Agent tool), по одной пачке на
   субагента. Промпт субагенту:
   - прочитай `M/MEASURE.md` целиком;
   - выполни `python3 "M/show.py" --batch N` (рабочая папка — из `SUMMARY.work`, передай её в
     `--work`);
   - размети каждую сессию по 12 колонкам по смыслу и запиши `flags_bN.json` в рабочую папку в
     формате из MEASURE.md;
   - тексты сессий никуда не копируй, в ответ верни только путь к файлу и счётчики.
   Одну-единственную пачку размечай сам без субагентов.
4. Выборочно проверь 2–3 сессии из чужих пачек (`python3 "M/show.py" --sid K`): разметка должна
   совпадать с твоей по смыслу. Расхождение больше чем на 1–2 привычки — переразметь пачку сам.

## Шаг 2. Фишки Claude и программа ЛАБС-6

1. `python3 "M/features.py"` — детект по `~/.claude` (skills, agents, commands, хуки в
   settings.json, plugins/installed_plugins.json, MCP в ~/.claude.json) и по следам в логах
   (слэш-команды, субагентские ветки, claude -p, /schedule, /code-review, воркфлоу GitHub).
2. Для слагов из `unknown` задай пользователю один короткий вопрос списком: «что из этого
   пробовал(а)? можно пропустить — тогда считаю, что нет». Ответы передай в compute.py через
   `--mark-used` / `--mark-unused`. Пропустил — так и скажи в результатах: непроверенное посчитано
   как неиспользуемое.
3. **Программа ЛАБС-6 против истории (КОНТРАКТ 6).** Открой `SKILL_DIR/program.md` — там 11
   пунктов актуальной программы (слаги `agent, research, site, platform, funnel, mcp-bot,
   miniapp, design, typography, payments, packaging`) и поле «Детект» с маркерами у каждого.
   По каждому слагу реши used или gap по корпусу замера:
   - прогони маркеры грепом по `clean_multiturn.json` в рабочей папке из `SUMMARY.work`
     (регистр не важен); маркер — только повод открыть сессию, зачёта по ключевому слову нет;
   - хиты проверь по смыслу (`python3 "M/show.py" --sid K`): зачёт, когда человек сам делал
     это или просил сделать в своей задаче; упоминание вскользь, чужой текст, планы — незачёт.
     Дисциплина та же, что у разметки привычек;
   - спорные слаги добавь в вопрос из пункта 2 тем же списком (один вопрос на всё, можно
     пропустить); пропуск и «нет» — gap.
   Каждый из 11 слагов попадает ровно в один список: `program_used` или `program_gaps`.
   Тексты сессий при этом никуда не копируй.

## Шаг 3. Результат

1. `python3 "M/compute.py" --name "Имя" [--mark-used ...] [--mark-unused ...]` — пишет
   `~/.claude/ii-master-result.json` (КОНТРАКТ 2, его читают страница, карточка и тренер; поле
   `mode: "auto"`). Прошлый результат сам уезжает в `ii-master-result.prev.json`.
2. Допиши в `~/.claude/ii-master-result.json` два поля из шага 2.3 — compute.py про программу
   не знает: прочитай файл и добавь `"program_used": [...]`, `"program_gaps": [...]` (массивы
   слагов из program.md, вместе покрывают все 11). Сделай это ДО запуска render.py — иначе блок
   программы на странице выйдет с подписью «не проверяли».
3. Сверь глазами таблицу из консоли с 2–3 размеченными сессиями: похоже ли на правду. Явная
   ошибка — вернись к разметке; числа не подгонять.

## Шаг 4. Питч и страница

1. Открой `SKILL_DIR/labs_map.md` и собери `pitch.html` (положи в рабочую папку замера):
   - обычный профиль: блоки по слагам из `growth` (1–2 привычки) — абзац питча и кейс-цитата
     дословно; если среди `features_unused` есть целая группа из labs_map — добавь один блок по
     группе;
   - `growth` пуст (все привычки на уровне базы, профиль не сильный) — питч только по группам
     неиспользуемых фишек; utm_content=tools render.py возьмёт сам;
   - сильный профиль (`extra.strong_profile` = true, по КОНТРАКТУ 5 это score11 ≥ 8): вместо
     этого блок «первые деньги»;
   - разметка: `<p>` для абзацев, `<blockquote>цитата — имя, участница ЛАБС 5</blockquote>` для
     кейсов; msg #id из labs_map на страницу не переносить — это внутренняя ссылка для проверки.
   Питч — 2–4 абзаца максимум; на странице он встаёт вступлением части «Что прокачаем именно
   у тебя» блока ЛАБС. Цену в питче не называть: render.py сам печатает её один раз у кнопок
   заявки, это единственное упоминание цены на странице. Остальные пробелы дописывать не нужно —
   render.py сам добавит под питчем строки по каждой привычке ниже базы (кроме разобранных в
   питче) и по группам неиспользуемых фишек; пробелы программы отдельными карточками не идут —
   они уже видны плашками в блоке «Программа ЛАБС-6 против твоей истории». Он же собирает части
   «Что такое ЛАБС», «Для кого» и список мини-курсов с подсветкой под пробелы.
2. `python3 "M/render.py" --pitch <путь к pitch.html> --open` — подставит данные в
   `SKILL_DIR/scorecard.html`, запишет `~/.claude/ii-master-result.html` и откроет в браузере.
   CTA страницы — заявка менеджеру: кнопки Telegram (первая) и WhatsApp из config.md, текст
   заявки (балл, метод, зона роста, имя) render.py собирает из `manager_prefill` и кладёт в обе
   ссылки сам; для MAX — строка с номером под кнопками. Готовые ссылки он печатает в консоль
   строками «заявка …» (чекаут-ссылка — резерв, идёт только в консоль). Правила подстановки
   (их выполняет render.py, руками HTML не править):
   - каждый плейсхолдер заменяется во ВСЕХ вхождениях — `{{mode_badge}}` и `{{score11}}` стоят в
     шаблоне дважды (шапка и тайлы);
   - `{{score_caption}}` — хвост заголовка страницы: авто → «в среднем за диалог», квиз →
     «в экспресс-тесте»; `{{score_note}}` — подпись к баллу в тайле: авто → «Привычка засчитывается
     диалогу, только если в нём проявилась. X — сколько привычек набирается в среднем за один твой
     диалог; посчитано по N диалогам.», квиз → «привычек показано в трёх заданиях»;
   - `{{above_base}}` — сколько привычек не ниже базы Anthropic (единицы в `habits` из result.json);
     это второй тайл «Выше среднего пользователя». Он показывается только в авто-замере: в квизе
     render.py скрывает его классом `{{above_tile_cls}}` = « off», потому что балл квиза уже равен
     числу показанных привычек. Числа «в среднем за диалог» и «выше среднего» разные, это не ошибка:
     первое — среднее по одному диалогу, второе — по каким привычкам частота выше базы;
   - `{{profile_note}}` — пояснение к полосам профиля: авто → про долю диалогов и частоту
     (зелёная полоса возможна и у привычки «через диалог»), квиз → про «показана в заданиях или нет»;
   - `{{program_html}}`, `{{program_note}}`, `{{program_foot}}` — блок «Программа ЛАБС-6 против
     твоей истории» (перед блоком ЛАБС): пункты по неделям из program.md с отметками ✓ «уже
     делаешь» / «пробел» по `program_used`/`program_gaps`; оба поля пустые → блок свёрнут в одну
     строку «Чек-лист программы пропущен — пройди перемер, и раздел заполнится» (каталог без
     отметок не показывается);
   - `{{labs_gaps_html}}` и `{{labs_courses_html}}` — блок ЛАБС: строки «пробел → чем закрывается»
     по labs_map.md (привычки и группы фишек; пробелы программы карточками не дублируются) и
     мини-курсы платформы: строками — только разделы с пометками «прямо про твой инструмент» /
     «под твой пробел», остальные одной строкой «и ещё N разделов: …». Всё это render.py делает
     сам, руками не собирать;
   - `{{ask_label}}`, `{{ask_tg_url}}`, `{{ask_wa_url}}`, `{{ask_max_btn}}`, `{{max_note_html}}`,
     `{{ask_prefill}}`, `{{manager_name}}`, `{{manager_phone}}`, `{{price}}`,
     `{{price_installment}}`, `{{defense_date}}` — блок заявки менеджеру (CTA): render.py
     заполняет их из блока «Менеджер продаж» config.md; текст заявки несёт балл, метод замера
     и зону роста; `{{ask_label}}` стоит ещё в якоре после «Итога замера» и в sticky-полосе;
   - пустой или отсутствующий `features_unused` — это «фишки не проверялись»: в `{{features_html}}`
     вместо пустого блока встаёт одна строка об этом (а если непроверенных нет потому, что всё
     используется, — строка «всё уже в работе»). Скажи об этом и в чате, чтобы человек не решил,
     что у него ноль фишек;
   - после подстановки в странице не должно остаться ни одной пары `{{ }}` — render.py
     предупреждает о незаполненных плейсхолдерах, такое предупреждение чини, не игнорируй.
3. Покажи результат в чате коротко и по-деловому:
   - эмодзи-полоса из result.json в порядке слагов + оба числа с пояснением: «в среднем за диалог
     X из 11 (база 3–4); выше среднего пользователя — N из 11 привычек» (полосу собирает render.py,
     поле в консоли; зелёный квадрат = привычка на уровне базы, поэтому зелёных квадратов может
     быть больше, чем X: квадраты — про частоту против базы, X — про один средний диалог);
   - 3 сильных привычки — с конкретикой из его же сессий (без цитирования чужих имён и секретов);
   - 1–2 зоны роста в позитивной рамке: что даст привычка, готовая строка-шаблон из MEASURE.md;
   - фишки: что уже использует, что нет;
   - программа ЛАБС-6: одной строкой — сколько из 11 пунктов уже трогает и 1–2 главных пробела
     (по program_used/program_gaps), подробности на странице;
   - строка: «Страница сохранена: ~/.claude/ii-master-result.html. Открыть снова — скажи:
     „открой мой результат ИИ-мастер“»; подать заявку в ЛАБС 6 — кнопки на странице (менеджер:
     Telegram / WhatsApp, для MAX — строка с номером);
   - строка: промежуточные файлы замера лежат в ~/.claude/ii-master-work — их можно посмотреть
     (там видно всё, что считалось) и удалить, на результат это не влияет, для перемера папка
     пересоберётся.

## Шаг 5. Три предложения после результата

Задай по очереди, без давления, любое можно пропустить:

1. Карточка для сторис или чата — скилл `share-card` (он сам сделает PNG и эмодзи-полосу).
2. Персональный тренер: объясни, что это скилл `ii-trener`, который уже установлен вместе с
   плагином; если человек согласится, ты запишешь его профиль в `~/.claude/ii-master-profile.json`,
   и тренер начнёт изредка подсказывать ровно его слабые привычки в обычной работе (одна короткая
   подсказка за сессию, без продаж). Спроси прямо: «собрать тебе персонального тренера?».
   Только при явном «да»: запиши `~/.claude/ii-master-profile.json` = содержимое result.json плюс
   поля `"consent_trener": true`, `"trener_since": "<сегодня YYYY-MM-DD>"`, `"uchet": []`
   (КОНТРАКТ 3) и скажи, что тренер теперь активен. Без «да» ничего не записывай и не меняй.
3. Перемер через месяц-другой: одной фразой — «скажешь "перемерь" — сравню с сегодняшним».

## Перемер («перемерь»)

Полный прогон заново: шаги 0–4. compute.py сам покажет дельту к прошлому result.json, render.py
заполнит на странице слот {{delta_html}} «было → стало» (при первом замере он пуст). В чате
назови 2–3 привычки с наибольшим сдвигом. Если
прошлый замер был квизом, скажи, что сравнение примерное: квиз ближе к лучшей сессии, авто-замер —
к среднему по реальной истории.

## Если что-то пошло не так

- Скрипт упал — покажи ошибку пользователю честно и предложи квиз-ветку, она работает без логов.
- Логов меньше 5 многоходовых — квиз; после 5+ реальных диалогов можно перемерить по истории.
- Пользователь спрашивает «что именно ты читаешь?» — покажи путь ~/.claude/projects и объясни:
  реплики нужны только для локального подсчёта, из них наружу идут нули и единицы разметки.
