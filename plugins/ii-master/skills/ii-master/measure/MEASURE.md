# Как проходит авто-замер «ИИ-мастер»

Всё считается локально: скрипты читают логи Claude Code на этом компьютере и пишут файлы в
рабочую папку `~/.claude/ii-master-work/` (переменная `II_MASTER_WORK`). В сеть ничего не уходит.
Ниже `M` — папка `measure/` этого скилла.

## Шаги

1. `python3 M/extract.py` — собирает реплики пользователя из `~/.claude/projects/*/*.jsonl`,
   отсекает ветки субагентов и результаты инструментов → `sessions.json`.
2. `python3 M/clean.py` — режет служебное (хуки, уведомления, вставки скиллов, продолжения сессий,
   картинки), отбрасывает одноходовые тривиальные сессии и сессии самого теста, схлопывает дубли
   (одинаковое первое сообщение в один день — остаётся самая длинная) → `clean_sessions.json`,
   `clean_multiturn.json` (2+ реплики). Печатает `SUMMARY {...}` с полями `multiturn`, `to_mark`,
   `substantive`, `route` (`auto` при 5+ многоходовых, иначе `quiz`).
   Параметры: `--substantive 11` (порог содержательной сессии, только для статистики),
   `--min-multiturn 5`, `--max-sessions 80` (размечаются самые свежие).
3. `python3 M/show.py --list` / `--batches` / `--batch N` / `--sid N [--full]` — показать реплики
   для ручной разметки. Пачка по умолчанию — 12 сессий, длинные реплики обрезаются до 2500 символов.
4. **Ручная разметка** (см. ниже) → файлы `flags_b1.json`, `flags_b2.json`, … в рабочей папке.
5. `python3 M/features.py` — какие фишки Claude Code человек уже использует → `features.json`
   (`used` / `unused` / `unknown`; `unknown` — то, что локально не видно: задать один вопрос).
6. `python3 M/compute.py --name "Имя" [--mark-used a,b] [--mark-unused c]` — профиль против базы
   Anthropic → `~/.claude/ii-master-result.json` (КОНТРАКТ 2). Прежний результат уезжает в
   `~/.claude/ii-master-result.prev.json`, в консоли — дельта по привычкам.
7. `python3 M/render.py --pitch pitch.html [--utm-content слаг] --open` — подстановка в
   `../scorecard.html` → `~/.claude/ii-master-result.html`, открыть в браузере.

## Разметка: дисциплина

Размечается каждая многоходовая сессия из `clean_multiturn.json`, по 12 колонкам, 0 или 1.
Порядок колонок фиксирован (КОНТРАКТ 1): `iter, goal, examples, format, mode, tone, context,
audience, reason, approach, fact, verify`. Файл разметки:

```json
{"cols": ["iter","goal","examples","format","mode","tone","context","audience","reason","approach","fact","verify"],
 "S7": [1,1,0,1,0,0,1,1,0,0,0,1],
 "S9": [1,0,0,0,1,0,1,0,1,0,0,0]}
```

Правила:

- Читать только реплики пользователя. Ответы модели и то, что модель сделала сама по своей
  инициативе, в зачёт не идут.
- 1 ставится, если поведение есть хотя бы в одной реплике сессии. Решает смысл, а не слова:
  «для мамы пятиклассника» — это адресат, хотя слова «адресат» нет; «почему 130? ты пересчитал?» —
  это спор с логикой. Ключевые слова не искать, регулярками не размечать.
- Сомнение решать по смыслу реплики; если человек делает то же самое другими словами — зачёт.
  Если поведение только угадывается — 0.
- Одна привычка на одну колонку: «сделай таблицу для директора» даёт format и audience, но не goal.
- Сессии с одной репликой в разметку не попадают (они уже отсеяны).
- В файлы разметки пишутся только нули и единицы. Цитаты из чужих диалогов, пути, имена и любые
  секреты из логов никуда не копируются — ни в отчёт, ни на страницу, ни в карточку.

## Определения зачёта (дословно из шпаргалки «11 привычек»)

Поставить задачу:

1. `goal` — «Мне это нужно, чтобы …» — зачем.
2. `audience` — «Читать будет …» — для кого.
3. `examples` — «Хорошо = … Такого быть не должно: … Приму по …» — образец и планка.
4. `format` — «Формат: …» — таблица / слайды / письмо / пдф.
5. `tone` — «Тон: …» — просто / по-деловому / как в примере.

Правила игры:

6. `context` — Приложи то, чего модель не знает: файл, ссылку, вводные.
7. `mode` — «Спорь со мной. Не хватает данных — спрашивай. Не уверен — скажи прямо.»
8. `approach` — «Сначала предложи 2–3 подхода с минусами. Делать пока ничего не надо.»

Разобрать ответ:

9. `iter` — Минимум три сообщения вдогонку: уточни → оспорь → доведи.
10. `reason` — «Откуда ты это взял? Пересчитай.»
11. `fact` — Проверь руками цифры, даты и названия — хотя бы три самых важных.

Пояснения к спорным случаям:

- `iter` — сессия из двух и более реплик, где вторая и дальше развивают первую задачу
  (уточнение, правка, «а теперь …»). Новая несвязанная задача во второй реплике — не итерация.
- `context` — человек принёс то, чего у модели нет: вставил текст, указал файл или путь, описал
  ситуацию, дал вводные. Просьба «посмотри файл X» — контекст; «сделай красиво» — нет.
- `mode` — назначил роль или правила работы: «будь критиком», «задавай вопросы, если не хватает
  данных», «ничего не меняй без моего ок», «работай как тимлид».
- `approach` — спросил, как подойти, до «сделай»: «как лучше», «какие варианты», «предложи план».
- `reason` — усомнился в логике ответа и попросил обосновать или пересчитать.
- `fact` — проверил конкретное утверждение модели или попросил проверить по источнику: «это точно
  так?», «проверь по документации», «откуда цифра».
- `verify` (12-я колонка, вне индекса) — попросил доказать, что результат работает: тест, запуск,
  лог, скриншот, «докажи».

## База Anthropic (доля диалогов с привычкой)

iter 85,7 · goal 51,1 · examples 41,1 · format 30,0 · mode 30,0 · tone 22,7 · context 20,3 ·
audience 17,6 · reason 15,8 · approach 10,1 · fact 8,7. Составной индекс 30,3 %, в среднем
3,33 привычки на диалог («3–4 из 11»). Источник: исследование AI Fluency Index (Anthropic Education
Report, январь 2026, 9 830 размеченных диалогов). Цифры приведены в `common.py`.

## Как считается результат (compute.py)

- `habit_rates[слаг]` — доля размеченных сессий с привычкой, %.
- `habits[слаг]` = 1, если доля не ниже базы Anthropic.
- `score11` = округлённое среднее число привычек на сессию (подпись «в среднем на диалог»).
- `composite_pct` — среднее долей по 11 привычкам.
- `strong` — до трёх привычек с наибольшим неотрицательным отрывом от базы (ниже базы в «сильное»
  не попадает); `growth` — привычки ниже базы, 1–2 слага; пустой, если все на уровне базы (питч
  тогда собирается по фишкам, `utm_content=tools`).
- `extra.strong_profile` — `score11 ≥ 8` (КОНТРАКТ 5, единое правило для авто и квиза): для питча
  берётся блок «первые деньги», `utm_content=first-money`.
- Фишки: `features.json` + ответы на «неизвестно» (`--mark-used`, `--mark-unused`). Колонка
  `verify` точнее регулярки: при 15 %+ сессий `verification` считается используемой.
  Не отвеченные «неизвестно» попадают в `features_unused` — пользователю об этом сказано.

## Разметка пачками через субагентов

При 15+ сессиях размечать пачками параллельно. Каждому субагенту: этот файл целиком, команда
`python3 M/show.py --batch N`, запрет копировать тексты куда-либо, формат ответа — JSON выше,
и путь, куда записать `flags_bN.json` (рабочая папка из `SUMMARY.work`). После всех пачек —
`compute.py`. Дубли уже схлопнуты в `clean.py`, `dedup.json` не нужен.

## Перемер

Тот же прогон. `compute.py` сам сохранит прошлый результат в `ii-master-result.prev.json`
и напечатает дельту; `render.py` при наличии прошлого result.json заполнит слот `{{delta_html}}`
на странице (при первом замере слот получает пустую строку) — КОНТРАКТ 5.

## Плейсхолдеры scorecard.html (render.py)

Текущий шаблон scorecard.html использует: `{{name}}` `{{mode_badge}}` (дважды) `{{date}}`
`{{score11}}` (дважды) `{{score_caption}}` `{{score_tile_k}}` `{{score_note}}` `{{above_base}}`
`{{above_tile_cls}}` `{{profile_note}}` `{{bars_html}}` `{{delta_html}}` `{{features_html}}`
`{{pitch_html}}` `{{labs_gaps_html}}` `{{labs_courses_html}}` `{{price}}` `{{cta_url}}`
`{{cta_label}}`. Замена простая текстовая, каждый плейсхолдер — во всех вхождениях; пустой
`features_unused` рендерится строкой «фишки не проверялись» вместо пустого блока. Блок ЛАБС
(`labs_gaps_html`, `labs_courses_html`) render.py собирает сам: строки пробелов — из полей
«Куда ведёт в ЛАБС» и «Кейс» в labs_map.md, мини-курсы — из списка COURSES в render.py
(пересечение с пробелами человека даёт пометку «под твой пробел»).

render.py дополнительно умеет (на случай смены шаблона): `{{composite_pct}}` `{{dialogs_n}}`
`{{base_per_dialog}}` `{{emoji_bar}}` `{{strong_html}}` `{{growth_html}}`
`{{features_used_html}}` `{{test_url}}` `{{handle}}` `{{test_name}}` и по каждому
слагу привычки `{{rate_<слаг>}}` `{{pct_<слаг>}}` `{{base_<слаг>}}` `{{cls_<слаг>}}`
`{{name_<слаг>}}` `{{flag_<слаг>}}`. Разметка строк полосы и элементов фишек синхронизирована с
HTML-комментариями внутри scorecard.html; менять — в обоих местах (константы в начале render.py).
